# תוכנית: סדר יום – מערכת לניהול זמן משפחתי

מסמך התכנון של המערכת. שלבים 0–4 (סעיף 10) מומשו בגרסה 1.0.0; הוראות התקנה ושימוש נמצאות ב-[README](../README.md).

מוקאפ דינמי שממחיש את התוכנית: https://claude.ai/artifact/GpY2yLWCvLwprHBdYAn29o

## 1. מטרה

לוח זמנים ביתי שרץ על שרת Umbrel בבית, ומאפשר:

- לשבץ דברים שקורים קבוע בשעות קבועות (אוכל, מקלחות, הרדמות, סידור, נקיון, עבודה, זמן אישי) ומשימות קבועות בשעות.
- לראות את הכל בתצוגה יומית, שבועית וחודשית.
- חשבון לכל משתמש, שיתוף בין משתמשים, וצפייה בלוח אחד בזמנים של שניהם עם הצלבה ביניהם.
- הפרדה בין סוגי משימות ובין סוגי שגרות.

מה לא בגרסה הראשונה: סנכרון דו־כיווני עם Google/Apple Calendar, אפליקציה נייטיבית, התראות. הם מופיעים בשלבים המאוחרים (סעיף 10).

## 2. מושגי יסוד

**שיבוץ** הוא היחידה הבסיסית: משהו שיש לו שעת התחלה, שעת סיום ובעלים. יש שני סוגי שיבוץ, והם מוצגים אחרת בלוח:

- **שגרה** – דבר שפשוט קורה בשעה הזו (ארוחת ערב, הרדמה, עבודה). מוצגת כבלוק צבוע מלא.
- **משימה** – דבר שצריך לבצע ואפשר לסמן כ"בוצע" לכל מופע בנפרד (איסוף מהגן, כביסה). מוצגת כמסגרת עם תיבת סימון.

**קטגוריה** – לכל סוג רשימת קטגוריות נפרדת, עם צבע. ברירת מחדל שנוצרת בהתקנה, וניתנת לעריכה:

- שגרות: אוכל, מקלחות, הרדמות, סידור, נקיון, עבודה, זמן אישי.
- משימות: בית ותחזוקה, סידורים וקניות, ילדים, בריאות.

הקטגוריות משותפות לכל הבית (לא אישיות), כדי שבלוח המשולב אותו צבע יסמן אותו דבר אצל שני המשתמשים.

**חזרתיות** – שיבוץ הוא או חד־פעמי (תאריך אחד) או סדרה שבועית: ימים בשבוע, שעות, תאריך התחלה, ואופציונלית תאריך סיום ו"כל N שבועות". זה מכסה את הצורך ("קבוע בשעות") בלי המורכבות של RRULE מלא.

**חריג** – שינוי במופע בודד של סדרה: דילוג, הזזה לשעה אחרת, או סימון בוצע. עריכת סדרה מציעה שלוש אפשרויות: רק המופע הזה, מכאן והלאה (מפצל את הסדרה), או כל הסדרה.

**בעלות** – שיבוץ שייך למשתמש אחד, או משותף לכמה משתמשים (ארוחת ערב של שניכם). שיבוץ משותף מופיע בלוח של כל המשתתפים ונספר לשניהם.

## 3. שיתוף והצלבה

**רמות שיתוף** – כל משתמש מחליט מה משתמש אחר רואה מהלוח שלו:

| רמה | מה רואים |
|---|---|
| תפוס בלבד | רק שהזמן תפוס, בלי שם ובלי קטגוריה |
| צפייה | את כל הפרטים, בלי אפשרות לשנות |
| עריכה | אפשר גם ליצור ולשנות שיבוצים בלוח של השני |

בנוסף, כל שיבוץ בודד אפשר לסמן **פרטי**: גם מי שיש לו הרשאת צפייה יראה אותו כ"תפוס".

**לוח משולב** – בתצוגת יום ושבוע כל יום מתחלק לשני מסלולים, אחד לכל משתמש (המשתמש המחובר תמיד ראשון). שיבוץ משותף נמתח על שני המסלולים. אפשר להדליק ולכבות כל לוח.

**הצלבה** – שכבה שמחשבת מעל שני הלוחות:

- **התנגשויות** – שני שיבוצים של אותו אדם שחופפים בזמן. מסומנים במסגרת אדומה, ומופיעים ברשימה עם קישור ליום.
- **פנויים יחד** – חלונות של שעה ומעלה שבהם אף אחד מהשניים לא משובץ, בתוך "שעות הפעילות" (ברירת מחדל 07:30–23:00, ניתן להגדרה).
- **חלוקת עומס** – סך השעות של מטלות בית וילדים לכל משתמש בטווח המוצג.

ההצלבה מחושבת בשרת, כך ששיבוץ פרטי של השני משתתף בחישוב בלי שהפרטים שלו נשלחים לדפדפן.

## 4. תצוגות

- **יום** – ציר שעות עם מסלול רחב לכל משתמש, ולצדו רשימת משימות היום לסימון וסיכום שעות לפי קטגוריה לכל משתמש.
- **שבוע** – שבעה ימים (ראשון עד שבת, מימין לשמאל), שני מסלולים צרים בכל יום. זו תצוגת ברירת המחדל במחשב; בטלפון ברירת המחדל היא יום.
- **חודש** – סדרות היו מציפות כל תא, לכן הן מתכווצות לנקודת צבע אחת לכל קטגוריה. בשמם מוצגים רק שיבוצים חד־פעמיים ומופעים שהוזזו. לחיצה על יום פותחת את תצוגת היום.

בכל התצוגות: סינון לפי קטגוריה ולפי סוג, ניווט קדימה/אחורה ו"היום", שעון 24 שעות, ממשק בעברית מימין לשמאל.

## 5. ארכיטקטורה

קונטיינר Docker אחד, בלי תלות בשירות חיצוני:

```
דפדפן / טלפון (PWA)
        │  HTTP + SSE
        ▼
┌──────────────────────────────┐
│  קונטיינר יחיד                │
│  שרת API (Node + Fastify)    │
│   ├─ קבצי ה-frontend הסטטיים │
│   ├─ מנוע חזרתיות והצלבה     │
│   └─ SQLite  →  /data        │
└──────────────────────────────┘
```

| שכבה | בחירה | למה |
|---|---|---|
| שפה | TypeScript בשרת ובלקוח | קוד משותף למנוע החזרתיות וטיפוסים משותפים |
| שרת | Node 22 + Fastify | קל, מהיר, מתאים לקונטיינר קטן |
| מסד נתונים | SQLite (קובץ אחד) + Drizzle למיגרציות | אפס תחזוקה, גיבוי = העתקת קובץ, מספיק בשפע למשפחה |
| לקוח | React + Vite + TanStack Query | אפליקציית עמוד אחד, ניתנת להתקנה כ-PWA במסך הבית של הטלפון |
| לוח | רכיב רשת משלנו, לא ספריית לוח שנה | מסלול לכל משתמש, RTL והצלבה הם לב המוצר, והרכיב קטן (המוקאפ מוכיח) |
| עדכון חי | SSE | כששותף משנה משהו, הלוח של השני מתעדכן בלי רענון |
| אימג' | multi-arch: amd64 + arm64, מתפרסם ל-GHCR מ-GitHub Actions | Umbrel רץ גם על x86 וגם על Raspberry Pi |

**אזור זמן** – שעות נשמרות כשעון מקומי (07:15) יחד עם אזור הזמן של ההתקנה (`Asia/Jerusalem`), לא כ-UTC. כך שגרה של 07:15 נשארת 07:15 גם אחרי מעבר לשעון קיץ.

## 6. מודל נתונים

```
users              id, username, display_name, password_hash, role(admin|member)
sessions           id (גיבוב המזהה), user_id, expires_at
invites            token, created_by, expires_at
categories         id, kind(routine|task), name, color, is_chore, sort, archived
settings           key, value                -- שעות פעילות, תאריך התקנה
entries            id, owner_id, kind, category_id, title, notes,
                   start_time, end_time,
                   date                      -- לחד־פעמי
                   days_mask, interval_weeks, start_date, end_date   -- לסדרה
                   is_private
entry_participants entry_id, user_id         -- שיבוץ משותף
entry_exceptions   entry_id, date, type(skip|move), start_time, end_time
task_completions   entry_id, date, done_by, done_at
shares             owner_id, grantee_id, level(busy|view|edit)
```

מופעים אינם נשמרים במסד. השרת פורש סדרות למופעים לפי הטווח המבוקש ומחיל עליהם חריגים וסימוני ביצוע.

## 8. אבטחה וחשבונות

- חשבונות מקומיים: שם משתמש וסיסמה (scrypt המובנה ב-Node, בלי תלות בספרייה מקומפלת), עוגיית session מסוג httpOnly. בשרת נשמר רק גיבוב של מזהה ה-session.
- המשתמש הראשון שנרשם הוא המנהל. משתמשים נוספים מצטרפים רק דרך קישור הזמנה.
- אין סודות בקובץ ה-compose: מזהי ה-session אקראיים ונשמרים במסד הנתונים שב-`/data`.
- כל בדיקות ההרשאה (תפוס/צפייה/עריכה/פרטי) נעשות בשרת.
- השרת לא נחשף לאינטרנט. גישה מחוץ לבית דרך Tailscale (קיים כאפליקציה ב-Umbrel).

## 9. פריסה על Umbrel

**שלב ראשון – Portainer.** הדרך המהירה להתחיל, Stack אחד:

```yaml
services:
  seder-yom:
    image: ghcr.io/tcbr10/time_management_system:latest
    restart: unless-stopped
    ports:
      - "8420:3000"
    environment:
      TZ: Asia/Jerusalem
    volumes:
      - seder-data:/data
volumes:
  seder-data:
```

לפי דף האפליקציה של Portainer בחנות של Umbrel, יש להשתמש רק ב-named volumes: מידע ב-bind mount אובד כש-Portainer מופעל מחדש או מתעדכן. קובץ ה-Stack שבריפו בנוי כך.

**שלב שני – אפליקציה ב-Umbrel Community App Store.** ריפו קטן עם `umbrel-app-store.yml` ותיקיית אפליקציה שמכילה `umbrel-app.yml` ו-`docker-compose.yml`. היתרונות: אייקון בדשבורד של Umbrel, עדכון בלחיצה, נתונים תחת `${APP_DATA_DIR}`.

```yaml
services:
  app_proxy:
    environment:
      APP_HOST: <store-id>-seder-yom_web_1
      APP_PORT: 3000
      PROXY_AUTH_ADD: "false"
  web:
    image: ghcr.io/tcbr10/time_management_system:<version>@sha256:<digest>
    restart: on-failure
    environment:
      TZ: Asia/Jerusalem
    volumes:
      - ${APP_DATA_DIR}/data:/data
```

`PROXY_AUTH_ADD: "false"` מבטל את מסך הסיסמה של Umbrel לפני האפליקציה. זה נחוץ כי ל-Umbrel יש סיסמה אחת, ואילו כאן לכל בן משפחה יש חשבון משלו בתוך המערכת.

**גיבוי** – עותק לילי של קובץ ה-SQLite לתיקיית `/data/backups` (נשמרים 14 אחרונים), וכפתור ייצוא ידני של כל הנתונים ל-JSON.

## 11. החלטות שהתקבלו

1. **שם המערכת** – "סדר יום".
2. **מי המשתמשים** – בני הבית בלבד, בלי חשבונות לילדים או למשפחה המורחבת. המודל עדיין תומך בכל מספר משתמשים.
3. **"עבור מי"** – לא נוסף שדה כזה; הבעלים של השיבוץ מספיק.
4. **התראות** – לא דחוף; נשאר בשלב 5.
5. **יומנים חיצוניים** – לא כעת.

## 12. מה נשאר מחוץ לגרסה 1.0.0

- שלב 5 כולו: תזכורות, גרירה לשינוי שעות, תבניות ופיד ICS.
- בדיקות קצה־לקצה אוטומטיות ב-CI. הזרימות נבדקו בדפדפן ידנית בסקריפט, אבל הוא לא חלק מהריפו.
- שיבוץ שחוצה חצות (למשל 22:00–06:00) אינו נתמך; יש לפצל אותו לשני שיבוצים.
